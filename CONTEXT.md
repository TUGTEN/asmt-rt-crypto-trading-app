# CONTEXT.md — Crypto Trading App (ubiquitous language)

Glossary only. No implementation details.

[- **Symbol**: BTC-USD, single simulated market. Synthetic seeded GBM generator (`--seed`/`SEED`, plus the scenario injector — spike/halt/gap/burst, see PROTOCOL.md). No second headline symbol; watchlist bonus deferred to Round 4.]
- **Trade**: A market event generated by the backend: ordering identifier (`seq`), timestamp, price, quantity. Trades are the atomic truth; everything else derives from them. There is no user `Order` in this app (no buy/sell required) — do not say "order" when you mean "trade".
- **OrderBook**: Plausible bids and asks (≥10 each side) derived around the trade mid-price. Consumed as REST `Snapshot` + WebSocket `Deltas`, each carrying `seq`/`prevSeq` for gap detection.
- **Snapshot**: Point-in-time copy of the book `{seq, bids, asks}` fetched over REST.
- **Delta**: Incremental book change `{seq, prevSeq, changes}` streamed over WebSocket. Apply only if `prevSeq` equals the last applied `seq`; otherwise refetch.
- **Candle (OHLCV)**: Open, high, low, close, volume over an `Interval`, aggregated from the full trade stream. Backend always computes the complete, correct candle; slower tiers only throttle *delivery*, never the values.
- **Interval**: Candle duration. Settled: `1s` + `1m`, configurable system-wide from a single source of truth (backend flag, validated by history/WS APIs, reflected in URL).
- **Tier**: Per-connection delivery level owned by the backend: `full`, `degraded`, `minimal`. Settled thresholds: full ≤150ms @4Hz, degraded ≤300ms @1Hz, minimal above @0.25Hz; 3 consecutive probes to downgrade, 5 to upgrade; 3 missed reports → degraded.
- **RTT**: `tRecv - tSend` from app-level WS ping-pong echo every 2s. `Latency` = RTT/2. `Jitter` = EMA of |RTT - prevRTT|. Client measures and reports; backend decides the tier.
- **Live vs Stale**: `Live` = connected and subscribed with fresh data. `Stale` = cached values shown while disconnected, tab hidden, or unsubscribed — never presented as live.
- **Session/Connection**: One WebSocket connection = one tier state machine. Reconnect = new session, must resubscribe and re-sync book from snapshot. This client holds two per mount: a market session (book + trades, redialed only on drop) and a chart session (candles + telemetry, redialed on interval switch too).
